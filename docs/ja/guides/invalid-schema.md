# Tiptap で不正なスキーマを扱う

> 原文: [https://tiptap.dev/docs/guides/invalid-schema](https://tiptap.dev/docs/guides/invalid-schema)

共同編集の環境では、コンテンツの整合性を保つのが大きな課題になることがあります。たとえば、異なるバージョンのアプリを使うユーザー同士が、同じドキュメントを編集しようとする場面です。シングルページアプリケーションでよくある場面もあります。ブラウザのタブを再読み込みせずに長時間開いたままのユーザーがいる一方で、最近ページを読み込んだばかりで常に最新のエディタを使っているユーザーもいます。

どちらの場合も、新しいバージョンのユーザーが、ほかのユーザーには使えない機能を使ってコンテンツを作ります。古いバージョンのユーザーがこのドキュメントを開いたとき、どうすればデータの消失を防ぎ、ドキュメントの構造を保ち、快適な使い心地を損なわずに済むでしょうか。

そこで重要になるのが、不正なスキーマの扱いです。コンテンツの構造がエディタの想定と合わない場面をうまく処理でき、データの破損、予期しないコンテンツの除去、エディタのクラッシュといった問題を防げます。

メモアプリ、コンテンツ管理システム、そのほかリッチテキスト編集の機能を持つどんなアプリケーションでも、スキーマを適切に扱う方法を理解して実装すれば、信頼性と使い心地を大きく高められます。

## コンテンツチェック

Tiptap には `enableContentCheck` というオプションがあります。`true` にすると、登録した拡張機能から作られるスキーマに照らしてコンテンツを検証する仕組みが有効になります。コンテンツのエラーがアプリケーションで問題を起こす前に検出して対処したいときに、特に役立ちます。

### コンテンツチェックを有効にする

この機能を有効にするには、Tiptap エディタの初期化時に `enableContentCheck` オプションを追加するだけです。

```jsx
new Editor({
  enableContentCheck: true,
  // ... ほかのオプション
})
```

## contentError イベント

コンテンツチェックが有効な場合、エディタのセットアップ時に渡した初期コンテンツがスキーマと合わないと、Tiptap は `contentError` イベントを発行します。このイベントには、エラーを適切に処理するのに役立つ情報が含まれます。

### contentError イベントを処理する

このイベントの処理方法は2つあります。

1つは `onContentError` コールバックを使う方法です。

```jsx
new Editor({
  enableContentCheck: true,
  content: potentiallyInvalidContent,
  onContentError({ editor, error, disableCollaboration }) {
    // ここにエラー処理のロジックを書く
  },
  // ... ほかのオプション
})
```

もう1つは、`contentError` イベントにリスナーを登録する方法です。

```jsx
const editor = new Editor({
  enableContentCheck: true,
  content: invalidContent,
  // ... ほかのオプション
})

editor.on('contentError', ({ editor, error, disableCollaboration }) => {
  // ここにエラー処理のロジックを書く
})
```

## コンテンツチェックを有効にせずに contentError イベントを受け取る

コンテンツチェックを有効にせずに `contentError` イベントだけを受け取りたい場合は、Tiptap エディタの初期化時に `emitContentError` を `true` にします。

```jsx
new Editor({
  enableContentCheck: false,
  emitContentError: true,
  // ... ほかのオプション
})
```

この設定では、エディタに不正なコンテンツがあってもそのまま扱えます。そのうえで、コンテンツが不正であることの通知は受け取れます。

## コンテンツの形式についての注意

Tiptap のコンテンツチェックは、JSON 形式のコンテンツに対しては 100% 正確です。一方、HTML 形式のコンテンツでは制約があります。Tiptap は足りないノードをできるかぎり検出して知らせますが、マークに関する問題は見逃すことがあります。

## 推奨するエラー処理の方針

スキーマのエラーをどう処理するかは、アプリケーションや要件によって変わります。一般的な推奨は次のとおりです。

### 共同編集を使わない場合

共同編集の機能を使っていなければ、未知のコンテンツを取り除く初期設定の挙動で十分かもしれません。これで、今後の編集に向けてコンテンツを有効とわかっている状態に保てます。

### 共同編集を使う場合

共同編集の機能を使う場合は、同期の問題を防ぐために、コンテンツのエラーを必ず処理してください。共同編集の環境でコンテンツのエラーを処理する例を示します。

```jsx
onContentError({ editor, error, disableCollaboration }) {
  // 不正なコンテンツが同期されないよう、共同編集を無効にする
  disableCollaboration()

  // 更新イベントを発行しない
  const emitUpdate = false

  // これ以上ユーザーが入力できないようにする
  editor.setEditable(false, emitUpdate)

  // 問題が起きたことをユーザーに知らせる
  notifyUser("An error occurred. Please refresh the application.")
}

```

この方法では、次のことを行います。

1. 不正なコンテンツが同期されないよう、共同編集を無効にする
2. 更新イベントを発行しないようにする
3. これ以上ユーザーが入力できないよう、エディタを無効にする
4. 問題が起きたことをユーザーに知らせる
